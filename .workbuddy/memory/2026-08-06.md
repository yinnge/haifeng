## ResourceController 权限调整（haifeng-app）
- 需求：资源列表（/list）公开不登录；查看资源 URL（/{id}/url）需 VIP 会员。
- 改动：将 `/{id}/url` 上的 `@RequireLogin` 改为 `@RequireVip`（import 同步替换）。`/list`、`/categories` 保持无注解（公开）。
- 关键澄清：权限体系用的是注解 + AuthAspect（@RequireVip 要求登录且 isVip()，否则抛 VIP_REQUIRED），不是枚举；用户口中的"改枚举"实为改注解。
- 鉴权链路：AuthAspect.checkVip → SecurityUtil.getCurrentUser() 为 null 抛 UNAUTHORIZED(401)；非 VIP 抛 VIP_REQUIRED(code=1005, msg="权限不足（需要旗舰版）")。GlobalExceptionHandler.handleBusinessException 对 BusinessException **返回 HTTP 200**，body 带 code，无 @ResponseStatus。
- 前端影响（D:\SelfCompany\Project-HaiFeng-fronted）：
  - 共享 request.ts 响应拦截器：code != 200 时 `Promise.reject(new Error(message))`，message 来自 data.msg。
  - List.vue 的 handleDownload catch 写的是 `e?.response?.data?.msg || '获取下载链接失败'`，但 wrapper 抛的是普通 Error（无 response 字段），所以 **永远走兜底文案**，且不会区分 VIP_REQUIRED。
  - 结论：接口契约未变，不会"坏"，但登录态非 VIP 用户点下载会看到误导性的"获取下载链接失败"。建议前端：(1) 用 e.message 取真实文案；(2) 识别 code 1005 弹"升级VIP"引导。
- 前端补丁已应用：D:\SelfCompany\Project-HaiFeng-fronted\apps\user\src\views\resource\List.vue 的 handleDownload catch 改为读取 `e.message`，并当 msg 含"旗舰版"/"VIP"时弹 ElMessageBox 引导开通，确认后 `router.push('/profile')`（与全站 goVip() 约定一致）。修复了原 `e?.response?.data?.msg` 永远取不到值的 bug。
