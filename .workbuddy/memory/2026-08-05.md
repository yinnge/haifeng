# 2026-08-05 工作日志

## 排查并修复：Docker Desktop 引擎假死（compose 报 500）

**现象**：`docker compose up -d` 报
`unable to get image 'redis:7-alpine': request returned 500 Internal Server Error ... check if the server supports the requested API version`
错误文案有误导性，实际与镜像、API 版本都无关。

**诊断证据**（`%LOCALAPPDATA%\Docker\log\`）：
- `docker version` 只输出 Client 段，Server 段缺失 → 引擎未运行
- `vm/init.log` 最后记录停在 8/4 23:04（VM 优雅关机），当日 8/5 记录数 = 0 → dockerd 从未启动成功
- `host/monitor.log`：`still waiting for the engine to respond to _ping after 35m: HTTP 500`，每秒重试全部 context deadline exceeded
- Docker Desktop GUI 进程存活，但连不上 WSL2 里的 dockerd → 所有 API 统一 500

**根因**：Docker Desktop 的 WSL2 后端引擎假死。GUI 有 watchdog 会自动重启自己，但不会重建 VM 状态，所以一直卡死。

**解法**（本机 WSL 命令被安全策略禁用，走的替代路径）：
1. PowerShell 杀光所有 Docker 进程：`Docker Desktop` / `com.docker.backend` / `com.docker.build` / `docker-sandbox`
   （注意：必须连 docker-sandbox 一起清，否则残留会让引擎复用旧状态）
2. `Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"` 重新拉起
3. 轮询 `docker version` 直到 Server 段出现

**结果**：引擎恢复（Docker Desktop 4.69.0 / Engine 29.4.0 / API 1.54），
`docker compose up -d` 成功，haifeng-postgres:5432 与 haifeng-redis:6379 均 healthy。

**环境备忘**：
- 本机 `wsl` / `wmic` / `sc` / `reg` / `schtasks` 等系统级命令被安全策略禁用，
  即使 dangerouslyDisableSandbox 也会被拦截。需要 WSL 操作时只能改用「杀进程 + 重启 Docker Desktop」路径，或让用户手动执行。
- PowerShell 工具的 stdout 经常被吞（exit 0 但无输出），验证类命令改用 Bash + tasklist/docker 更可靠。
- WSL 数据目录在 `D:\AppStoreElse3\docker\DockerDesktopWSL`，虚拟磁盘配额约 119GB，D 盘满也会导致引擎起不来。
- 项目 compose 服务：postgres:16-alpine(5432) + redis:7-alpine(6379)，
  数据卷 postgres_data / redis_data，网络 haifeng-network，均带 healthcheck。

## 排查「8080/8081 端口被占用」误报（已更正根因）
现象：haifeng-app(8080)/haifeng-admin(8081) 启动报 Port already in use 后秒退(exit 1)，netstat 查无监听、无后端进程。
**真正根因（2026-08-05 用 netsh 确认）**：本机装了 Docker Desktop/WSL2，Windows 把 7891~9090 这一整片端口划成了
「保留端口区间」(`netsh interface ipv4 show excludedportrange protocol=tcp` 可见 7991-8090 含 8080、8091-8190 含 8081)。
保留区间 netstat 看不到监听，但任何程序 bind 都会被拒并谎报"已被占用"。之前的 TIME_WAIT/旧实例判断是错的——
**端口根本没被进程占，是 Windows 自己锁的**，所以重启/等待都没用。
**修复**：把默认端口移出保留区间 —— app 8080→18080、admin 8081→18081（application.yml 的 ${APP_PORT:18080}/${ADMIN_PORT:18081}）。
已确认 18080/18081 空闲且不在任何保留区间。
**重要**：端口用 `${ADMIN_PORT:...}` 环境变量覆盖写法，若 IDEA Run 配置里设了 ADMIN_PORT/APP_PORT 环境变量，会盖过 yml 默认值，
必须把这两个变量也改成 18081/18080，或删掉让默认值生效。
**替代方案（不推荐）**：保留 8080/8081 需释放 Docker/Hyper-V 的保留区间（停 Docker→netsh 释放→先绑端口再起 Docker），脆弱且重启易复发。
**自查命令**：`netsh interface ipv4 show excludedportrange protocol=tcp` 看端口是否在区间内；`netstat -ano | findstr :8080` 看是否真有 LISTENING。
**补充(17:30 更正)**：端口是动态的，从项目根 `.env`(D:/exeProject/ideaProjects/Project-HaiFeng/.env) 读取，
yml 用 `${ADMIN_PORT}`/`${APP_PORT}` 占位（非字面量）。已把 `.env` 的 `ADMIN_PORT=8081→18081`、`APP_PORT=8080→18080`
（落在 Windows 保留区间 7891-9090 之外）。yml 默认值也兜底成 18081/18080。
注意：若 IDEA Run 配置的 Environment variables 里显式写了 ADMIN_PORT/APP_PORT，会盖过 .env，需同步改或删掉。
